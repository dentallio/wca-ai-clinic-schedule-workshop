# Stage 4：用自然語言客製診所規則

## 練習 prompt

> 目標：當任一班別的虛構助理少於 2 人時，顯示「人力不足」警示。背景：現有週班表可新增與修改班別。限制：不要自動替人排班；不要加入病人欄位；不要修改 Firebase Security Rules、核心集合名稱或既有資料；如需資料結構變更先停下說明。驗收：0、1 人時顯示警示，2 人以上不顯示；重新整理後結果一致；既有醫師排班與休假功能仍通過。請先列出計畫、風險與測試案例。

## 三層驗收

1. 正常：同一日期與診別排入兩名虛構助理，該警示消失。
2. 邊界：只有一人時顯示警示，加入第二人才消失。
3. 衝突：醫師班或休假不得被誤算為助理人數。

接著重新執行 Stage 3 的六個手動步驟，並執行：

```bash
npm run test
```

規則只能顯示警示，不得自動決定真實人事安排。需求若轉向登入、權限、真實請假、HIS 或跨診所資料，立刻停止 Demo 路線。

## Checkpoint

- 0／1／2 人自動測試通過。
- 畫面顯示警示總數與日期／班別。
- Stage 3 回歸測試仍通過。
- commit 前 Review changes 沒有修改 `firestore.rules` 或核心集合名稱。
